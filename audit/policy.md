# AudiToad audit requirements

Live model calls require an explicit request, and every endpoint must be permitted by the
profile's allowed egress.
An experimental semantic observation must remain unresolved even when its suggested result
is pass. Unknown or missing evidence must not become a passing result.

A provider response must name the configured model and exactly the requested check, contain
a finite probability within zero and one, and have valid positive token usage.

Every declared rule/target pair must receive a terminal record. A refused budget must not
drop the remaining pairs. Terminal record order and count must agree with the declared work
and the canonical progress and audit owners before a clear outcome is returned.

A report must not overwrite a baseline, source input, known-answer input, mock input or
credential file. A publication failure must not produce a successful publication receipt.

Evidence files must remain inside their declared root. Links, parent traversal, stale hashes,
missing required roles and unsupported manifest fields must refuse before provider dispatch.
Selection must retain complete named source owners. Provider requests must use their local
syntax captures, with any semantic helper excerpts checked against that selected code.
An incomplete or mismatched selection is unresolved evidence.

Duplicate JSON keys and unsupported schema fields must fail validation rather than silently
choose a value. These checks concern the supplied source paths and do not establish complete
application security or all-platform behavior.
